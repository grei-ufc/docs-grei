    Como Automatizar a Criação do Diretório de Trabalho (Scripts .ps1 e .sh)

    Criar manualmente todas as pastas (src/, tests/, data/raw/, data/processed/, docs/), configurar o .gitignore científico, adicionar a licença MIT, preparar o mkdocs.yml e inicializar o Git a cada novo projeto de pesquisa pode ser trabalhoso e sujeito a esquecimentos.

    Para padronizar todos os repositórios do GREI-UFC, disponibilizamos dois scripts oficiais de automação (scaffolding) — um em PowerShell (.ps1) para Windows e outro em Bash (.sh) para Linux e macOS — que constroem todo o diretório de trabalho em menos de um segundo!

    Problema

    Você vai iniciar um novo projeto de Iniciação Científica, TCC ou Pós-graduação (em Python, Julia, MATLAB/Octave ou C/C++) e quer gerar automaticamente toda a estrutura de diretórios, arquivos de configuração, código de exemplo com teste unitário (padrão AAA) e repositório Git já inicializado na branch main.

    Solução: Scripts Oficiais init-projeto-grei

    Passo 1: Baixe o Script para o seu Sistema Operacional

    Você pode baixar os scripts diretamente pelos links abaixo (ou encontrá-los na pasta scripts/ deste repositório):

    • Windows (PowerShell): ⬇️ Baixar init-projeto-grei.ps1
    • Linux / macOS (Bash): ⬇️ Baixar init-projeto-grei.sh

    Passo 2: Execute o Script Escolhendo o Nome e a Linguagem

    Ambos os scripts recebem dois parâmetros e suportam nomes de pastas no padrão kebab-case (ex: nome-teste, controle-inversor) ou snake_case:

    1. NomeProjeto (opcional, padrão: meu-projeto-grei): Nome da pasta que será criada. O script converte automaticamente os hifens nos arquivos internos de cada linguagem (ex: nome-teste no pyproject.toml, NomeTeste no Project.toml da Julia e nome_teste no CMakeLists.txt do C/C++).
    2. Linguagem (opcional, padrão: python): Aceita python, julia, matlab ou c.

    Abra o terminal na pasta onde deseja criar o projeto e execute:

    # Cria um projeto em Python (padrão) com nome em kebab-case
powershell -ExecutionPolicy Bypass -File .\init-projeto-grei.ps1 controle-inversor

# Ou especifique outra linguagem científica (julia, matlab ou c):
powershell -ExecutionPolicy Bypass -File .\init-projeto-grei.ps1 fluxo-potencia julia
powershell -ExecutionPolicy Bypass -File .\init-projeto-grei.ps1 conversor-buck matlab
powershell -ExecutionPolicy Bypass -File .\init-projeto-grei.ps1 pll-embarcado c

    Execução direta caso a política do PowerShell já esteja liberada

    Se você já configurou Set-ExecutionPolicy RemoteSigned -Scope CurrentUser no seu Windows, pode rodar diretamente: 

    .\init-projeto-grei.ps1 nome-teste python


    # Conceda permissão de execução ao script (apenas na primeira vez)
chmod +x init-projeto-grei.sh

# Cria um projeto em Python (padrão) com nome em kebab-case
./init-projeto-grei.sh controle-inversor

# Ou especifique outra linguagem científica (julia, matlab ou c):
./init-projeto-grei.sh fluxo-potencia julia
./init-projeto-grei.sh conversor-buck matlab
./init-projeto-grei.sh pll-embarcado c

    O que o Script Gera Automaticamente?

    Ao ser executado, o script realiza 6 etapas automatizadas:

    1. Hierarquia de Pastas Padrão: Cria data/raw/ e data/processed/ (já com arquivos .gitkeep), docs/ subdividida nos 4 quadrantes Diátaxis (explanation/, tutorials/, how-to/, reference/) e .github/workflows/.
    2. Governança e Proteção de Dados: Gera o arquivo .gitignore científico multilíngue e a licença aberta LICENSE (MIT — GREI-UFC).
    3. Portal de Documentação + CI/CD: Gera o mkdocs.yml configurado com o tema Material em português, a página inicial docs/index.md e o workflow .github/workflows/deploy.yml para publicação automática no GitHub Pages.
    4. Arquitetura Específica da Linguagem Escolhida:
    5. Python (python): Cria src/, tests/, notebooks/, .python-version (3.12), .pre-commit-config.yaml e pyproject.toml já configurado com pytest, ruff, mkdocs-material e pythonpath = ["."].
    6. Julia (julia): Cria src/, test/, scripts/ e Project.toml.
    7. MATLAB / Octave (matlab): Cria src/, tests/, scripts/, models/ e o script startup.m que configura o path automaticamente.
    8. C / C++ (c): Cria include/, src/, tests/ e o CMakeLists.txt integrado ao CTest.
    9. Código Inicial + Teste Unitário (Padrão AAA): Cria uma função matemática documentada com unidades físicas em src/ e seu respectivo teste automatizado em tests/ pronto para rodar!
    10. Inicialização do Git: Executa git init, define a branch principal como main, adiciona todos os arquivos e registra o primeiro commit semântico (feat: inicializa estrutura padrao do projeto GREI-UFC).

    Código-Fonte dos Scripts

    Caso prefira copiar e colar o código diretamente, clique abaixo para expandir o script correspondente ao seu sistema operacional:

    <#
.SYNOPSIS
    Script de automação para criar e inicializar a estrutura padrão de projetos científicos do GREI-UFC.

.DESCRIPTION
    Cria a hierarquia de diretórios (src, tests, data/raw, data/processed, docs Diátaxis, .github/workflows),
    arquivos de governança (.gitignore científico, LICENSE MIT, README.md, mkdocs.yml),
    código-fonte inicial com teste unitário no padrão AAA para a linguagem escolhida
    (python, julia, matlab ou c) e inicializa o repositório Git com o primeiro commit.
    Suporta nomes de diretórios em kebab-case (ex: "nome-teste", "controle-inversor") ou snake_case.

.PARAMETER NomeProjeto
    Nome da pasta do projeto a ser criada (padrão: "meu-projeto-grei").

.PARAMETER Linguagem
    Linguagem principal do projeto: "python" (padrão), "julia", "matlab" ou "c".

.EXAMPLE
    .\init-projeto-grei.ps1 nome-teste
    .\init-projeto-grei.ps1 controle-inversor python
    .\init-projeto-grei.ps1 fluxo-potencia julia
    .\init-projeto-grei.ps1 conversor-buck matlab
    .\init-projeto-grei.ps1 pll-embarcado c
#>

param (
    [Parameter(Position = 0, Mandatory = $false)]
    [string]$NomeProjeto = "meu-projeto-grei",

    [Parameter(Position = 1, Mandatory = $false)]
    [ValidateSet("python", "julia", "matlab", "c")]
    [string]$Linguagem = "python"
)

$ErrorActionPreference = "Stop"
$AnoAtual = (Get-Date).Year.ToString()
$Linguagem = $Linguagem.ToLower()

# Remove barras finais caso o usuário digite "nome-teste/" ou ".\nome-teste\"
$NomeProjeto = $NomeProjeto.Trim().TrimEnd('/', '\')
if ($NomeProjeto.StartsWith("./") -or $NomeProjeto.StartsWith(".\")) {
    $NomeProjeto = $NomeProjeto.Substring(2)
}

if ([string]::IsNullOrWhiteSpace($NomeProjeto)) {
    Write-Error "O nome do projeto não pode ser vazio."
    exit 1
}

if (Test-Path -Path $NomeProjeto) {
    Write-Error "A pasta '$NomeProjeto' já existe neste diretório. Escolha outro nome ou remova a pasta existente."
    exit 1
}

# Gera identificadores normalizados a partir de nomes com hífen (ex: "nome-teste")
# 1. kebab-case para pacotes Python (ex: "nome-teste")
$NomeKebab = ($NomeProjeto.ToLower() -replace '[^a-z0-9_-]', '-' -replace '_+', '-' -replace '-+', '-').Trim('-')
# 2. snake_case para CMake / identificadores C (ex: "nome_teste")
$NomeSnake = ($NomeProjeto.ToLower() -replace '[^a-z0-9_]', '_' -replace '_+', '_').Trim('_')
if ($NomeSnake -match '^[0-9]') { $NomeSnake = "proj_$NomeSnake" }
# 3. PascalCase para módulos/projetos Julia (ex: "NomeTeste")
$PartesNome = $NomeProjeto -split '[^a-zA-Z0-9]+' | Where-Object { $_ -ne "" }
$NomePascal = ($PartesNome | ForEach-Object { $_.Substring(0,1).ToUpper() + $_.Substring(1).ToLower() }) -join ""
if ([string]::IsNullOrWhiteSpace($NomePascal) -or $NomePascal -match '^[0-9]') {
    $NomePascal = "Projeto$NomePascal"
}

Write-Host "==========================================================" -ForegroundColor Cyan
Write-Host " Inicializando projeto GREI-UFC: $NomeProjeto ($Linguagem)" -ForegroundColor Cyan
Write-Host "==========================================================" -ForegroundColor Cyan

# 1. Criação dos diretórios base comuns
$PastasComuns = @(

    "$NomeProjeto/data/processed",
    "$NomeProjeto/docs/explanation",
    "$NomeProjeto/docs/tutorials",
    "$NomeProjeto/docs/how-to",
    "$NomeProjeto/docs/reference",
    "$NomeProjeto/.github/workflows"
)

foreach ($Pasta in $PastasComuns) {
    New-Item -ItemType Directory -Path $Pasta -Force | Out-Null
}

# Arquivos .gitkeep para preservar a estrutura de dados vazia no Git
New-Item -ItemType File -Path "$NomeProjeto/data/raw/.gitkeep" -Force | Out-Null
New-Item -ItemType File -Path "$NomeProjeto/data/processed/.gitkeep" -Force | Out-Null

def calcular_potencia_media(tensoes: list[float], resistencia: float) -> float:
    """Calcula a potência ativa média dissipada em um resistor.

    Args:
        tensoes: Vetor de leituras instantâneas de tensão [V].
        resistencia: Resistência elétrica nominal [Ohms]. Deve ser > 0.

    Returns:
        Potência ativa média dissipada [W].
    """
    if resistencia <= 0:
        raise ValueError("A resistência deve ser estritamente positiva [Ohms].")
    if not tensoes:
        return 0.0
    potencias = [(v ** 2) / resistencia for v in tensoes]
    return sum(potencias) / len(potencias)

module CalculosRede

export calcular_potencia_media

"""
    calcular_potencia_media(tensoes::AbstractVector{<:Real}, resistencia::Real) -> Float64

Calcula a potência ativa média [W] dissipada em um resistor [Ohms].
"""
function calcular_potencia_media(tensoes::AbstractVector{<:Real}, resistencia::Real)::Float64
    resistencia <= 0 && throw(ArgumentError("A resistência deve ser positiva [Ohms]."))

function p_media = calcular_potencia_media(tensoes, resistencia)

def calcular_potencia_media(tensoes: list[float], resistencia: float) -> float:
    """Calcula a potência ativa média dissipada em um resistor.

    Args:
        tensoes: Vetor de leituras instantâneas de tensão [V].
        resistencia: Resistência elétrica nominal [Ohms]. Deve ser > 0.

    Returns:
        Potência ativa média dissipada [W].
    """
    if resistencia <= 0:
        raise ValueError("A resistência deve ser estritamente positiva [Ohms].")
    if not tensoes:
        return 0.0
    potencias = [(v ** 2) / resistencia for v in tensoes]
    return sum(potencias) / len(potencias)

    float p = pi->kp * erro;
    pi->integrador += pi->ki * pi->ts * erro;

    if (pi->integrador > pi->saida_max) pi->integrador = pi->saida_max;
    if (pi->integrador < pi->saida_min) pi->integrador = pi->saida_min;

    float saida = p + pi->integrador;
    if (saida > pi->saida_max) saida = pi->saida_max;
    if (saida < pi->saida_min) saida = pi->saida_min;

    return saida;
}
